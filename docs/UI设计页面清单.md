>
> - 仓库：`https://github.com/AbinCheungCom/Signify`

## 0. 使用说明

本清单按**代码实际实现的页面与路由**整理，供 UI 设计师逐页出稿。每个页面除主体布局外，还需覆盖其**关键状态**（空态 / 登录前后 / Flash 提示 / 分页 / 响应式 / 权限态），并在最后定义**全局设计系统组件**。

> ⚠️ 标记 `待新建` 的页面当前仓库中不存在，需要在设计中一并补充（见 §5）。

## 2. 公开页面（无需登录）

### 2.1 首页 `/`

- **导航栏**：品牌 Logo「Signify」+ 「企业家库」入口 + 「登录 / 个人中心」切换
- **主体**：推荐企业家大图展示（摄影主导，Tesla 风格，最多 6 位）
- **页脚**：品牌信息
- **设计状态**：推荐位不足（1~2 位）时的占位；无推荐时的空态

### 2.2 企业家库 `/entrepreneurs`

- **导航栏**：固定顶部、毛玻璃；「企业家库」高亮；登录状态切换「个人中心 / 登录」
- **筛选区**：搜索输入框 + 行业下拉 + 城市下拉 + 筛选按钮
- **统计行**：共 N 位企业家
- **卡片网格**：方图（头像）+ 姓名 + 行业·城市 + 简介（截断）+ 「推荐」徽章
- **分页**：上一页/下一页 + 当前页/总页数
- **页脚**
- **设计状态**：无结果空态；分页首/中/尾页；移动端网格 3 列 → 1 列

### 2.3 企业家详情 `/entrepreneurs/{id}`

- 头像 / 姓名 / 行业·城市 / 简介 / 联系电话 / 联系邮箱
- 返回列表导航
- **设计状态**：资料字段不全（缺头像/缺简介）时的排版

## 3. 认证流程（游客）

均为 Breeze 标准表单，建议统一出一套**认证页骨架**（居中卡片 + 品牌标识 + 输入框 + 主按钮）：

| 页面 | 路由 | 表单元素 |
|---|---|---|
| 登录 | `/login` | 邮箱 + 密码 + 「忘记密码」链接 |
| 注册 | `/register` | 姓名 + 邮箱 + 密码 + 确认密码 |
| 忘记密码 | `/forgot-password` | 邮箱 + 发送重置链接 |
| 重置密码 ⚠️待新建 | `/reset-password/{token}` | token（隐藏）+ 邮箱 + 新密码 + 确认密码 |
| 邮箱验证 | `/verify-email` | 提示文案 + 「重新发送验证邮件」按钮 |
| 密码确认 | `/confirm-password` | 密码输入 + 确认 |

**设计状态**：表单校验错误提示；发送/提交后的成功反馈；重置链接失效提示。

## 4. 登录后页面

### 4.1 个人资料 `/my/profile`（登录用户）

**三态合一**，是唯一的个人操作页：

| 状态 | 触发条件 | UI 内容 |
|---|---|---|
| ① 未创建 | 用户无档案 | 引导卡片 + 创建表单（仅姓名） |
| ② 已创建·编辑中 | 用户有档案 | 姓名 / **头像上传** / 行业 / 城市 / 简介 / 联系电话 / 联系邮箱 + 保存 |
| ③ 已提交待审核 | status=pending | 提交状态提示 + 允许编辑 |

**设计状态**：头像上传（拖拽/选择、预览、格式/大小校验错误）；未审核时后台不可见的说明。

### 4.2 后台首页·待审核 `/admin/dashboard`（管理员）

- **导航**：待审核 / 全部企业家 两个 Tab + 返回首页
- **统计区**：4 个统计卡片 —— 全部 / 待审核（黄）/ 已通过（绿）/ 已拒绝（红）
- **待审核列表**：头像 + 姓名 + 行业·城市 + 简介（截断）+ **通过 / 拒绝 / 查看** 按钮
- **分页**
- **设计状态**：无待审核空态；Flash 成功提示（审批后）

### 4.3 全部企业家管理 `/admin/entrepreneurs`（管理员）

- **筛选区**：状态筛选（全部/待审核/已通过/已拒绝）+ 搜索
- **列表/表格**：含 **推荐置顶切换**、**删除**、单个 **通过/拒绝**
- **批量操作**：多选 + **批量通过 / 批量拒绝**
- **设计状态**：批量操作确认弹窗；空筛选结果；删除确认弹窗

## 5. 安装向导 `/setup`（安装期）

多步流程，需设计**步骤状态**：

| 步骤 | UI 内容 |
|---|---|
| ① 数据库连接测试 | host / port / 数据库名 / 账号 / 密码 + 「测试连接」 |
| ② 安装配置 | 应用名 / 应用 URL / 管理员邮箱 / 管理员密码 + 确认密码 + 「安装」 |
| ③ 已安装 | 仅显示"系统已安装"提示，禁止重复操作 |

**设计状态**：连接成功/失败反馈；安装进行中；安装完成跳转引导。

## 6. 全局设计系统组件

以下组件在多个页面复用，建议在设计稿中作为**独立资产**先定义：

| 组件 | 说明 |
|---|---|
| 导航栏 / 页脚 | 公开、后台两套变体 |
| 按钮 | 主 / 次 / 危险 / 幽灵 / 禁用 |
| 输入框 / 下拉 / 搜索框 | 含校验错误态 |
| 分页 | 首/中/尾页 |
| 卡片 | 网格卡片、列表卡片 |
| 头像 | 含上传（预览、拖拽、错误态） |
| 状态徽章 | 待审核 / 已通过 / 已拒绝 / 推荐 |
| 弹窗确认 | 通过 / 拒绝 / 删除 / 批量操作 |
| Flash 提示 | 成功（绿）/ 错误（红）横幅 |
| 空态 | 无数据占位（列表、后台、推荐位） |
| 响应式 | 导航折叠、网格 1/2/3 列断点 |

## 7. 视觉现状与设计 tokens 方向

### 7.1 当前视觉（Tesla 风格，硬编码）

| Token | 值 | 用途 |
|---|---|---|
| 主色 | `#3E6AE1` | 主按钮、选中态、链接高亮 |
| 主色 hover | `#3558c4` | 按钮 hover |
| 背景 | `#F4F4F4` | 页面浅灰背景、Tab 选中、卡片底色 |
| 边框 | `#EEEEEE` | 分隔线、卡片描边 |
| 文字主 | `#171A20`（gray-900） | 标题/正文 |
| 文字次 | gray-500 / gray-400 / gray-300 | 说明、弱化文字 |
| 语义色 | green-600 / red-600 / yellow-600 | 已通过 / 已拒绝 / 待审核 |

> 现状：以上颜色以 `bg-[#…]` 等任意值硬编码散落在各页面，无统一 tokens。

### 7.2 设计方向建议

1. **方案一（保留）**：沿用现有色板，仅收敛为 `tailwind.config.js` 语义 tokens，风格不变。
2. **方案二（品牌化）**：对齐 ABIN 品牌（纯黑 + 单色 + 巨型字标）重定义色板，全站替换硬编码色。

选定方向后，设计 tokens 可直接落到 `tailwind.config.js` 的 `theme.extend.colors`，由开发替换全站任意值。

## 8. 设计交付建议

- 每页交付：**桌面稿 + 移动稿 + 关键状态**（空态、错误、权限态）
- 组件资产先行：先定 §6 组件，再拼页面
- 认证 6 页出一套骨架即可
- 后台 2 页与个人中心共用状态徽章、Flash、弹窗确认
- 交付格式建议：Figma 页面/框架命名与路由一致（如 `01-home`、`04-login`）
