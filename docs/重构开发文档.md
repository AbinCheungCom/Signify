> - 技术栈（已落地）：**Laravel 11 + Blade + Alpine.js + 静态 Tailwind**（去 Inertia / Vite）

## 1. 文档目的与范围

- **重构 ≠ 重写后端**：保留 Laravel、数据库、模型、迁移、权限（Policy/Middleware）、控制器业务逻辑。
- **前端去 Inertia**：12/13 个页面由 `.vue` 改为 Blade 服务端渲染，交互用 Alpine.js，样式用静态 Tailwind。
- 范围：不含新业务功能开发。
- 目标：让系统在现有 1.8G 服务器上**稳定、低依赖、可维护**地运行。

## 5. 总体策略

```
阶段0 准备 ─► 阶段1 P0 仓库健康化 ─► 阶段2 去Inertia/Blade重写 ─► 阶段3 后端卫生+测试+CI ─► 阶段4 品牌化(可选)
 (0.5天)      (1-2天 · 必须)         (4-5天 · 核心)               (1-2天)                  (按需)
```

- **阶段 1 是必经之路**：任何路线都要先让仓库可运行。
- **阶段 2 是本方案核心**：前端去 Inertia 改 Blade + Alpine。
- 每阶段结束均为**可上线稳定状态**。

### 阶段 2：去 Inertia → Blade + Alpine（约 4-5 天，核心）✅ 功能完成，视觉精调待设计稿

#### 2.1 移除 Inertia / Vite 前端依赖
- `composer remove inertiajs/inertia-laravel`（如已装）；删除 Inertia 中间件引用
- `package.json` 移除 `@inertiajs/vue3`、`@vitejs/plugin-vue`、`laravel-vite-plugin`、`vite`
- 删除 `vite.config.js`；删除 `resources/js/app.js` 的 Inertia 引导
- 保留 `resources/css/app.css`（或并入静态 Tailwind）

#### 2.2 控制器改造（10 个控制器）
- 所有 `inertia('Page', [...])` → `view('pages.xxx', [...])`

- 分页数据直传 Blade（`->links()` 或自定义分页视图）

#### 2.3 静态资源落地（工作站构建，入库）
- 工作站用 Tailwind 构建一次 → 提交 `public/css/app.css`
- 下载 `alpine.min.js` → 提交 `public/js/alpine.min.js`
- **服务器零构建、零 CDN 依赖**（离线可跑）

#### 2.4 Blade 模板（13 页，按新 UI 设计稿）
- 布局：`resources/views/layouts/app.blade.php`（公开）、`layouts/admin.blade.php`（后台）
- 页面：首页 / 企业家库 / 详情 / 登录 / 注册 / 忘记密码 / **重置密码(新增)** / 邮箱验证 / 密码确认 / 个人资料 / 后台首页 / 全部管理 / 安装向导
- 抽 partial：导航、页脚、分页、Flash 提示、空态
- 表单：CSRF + `@method`；头像上传表单；批量操作表单
- 交互（Alpine）：批量选择、弹窗确认、筛选
- 样式按 `UI设计页面清单.md` 与设计稿实现

#### 2.5 Setup 向导
- 路由已并入 web.php（阶段 1）；页面改 Blade，保留"数据库连接测试 → 安装 → 已安装"三步状态

## 7. 明确不做的事（Anti-goals）

| 方向 | 决策 | 理由 |
|---|---|---|
| 前后端分离（API + SPA） | 不做 | CRUD + 认证不需要 SPA；增加双端成本 |
| 模块化 / DDD 分层 | 不做 | 2 个模型的规模，分层收益为负 |
| **TypeScript 化** | 不做 | 走 Blade 后前端无框架，TS 不再适用（v1 该条作废） |
| Docker 化 | 不做 | 服务器未装 Docker，1.8G 内存跑容器不现实 |
| 数据库重构（enum 等） | 不做 | MariaDB 5.7 兼容是部署要求 |

## 9. 风险与回滚

| 风险 | 等级 | 缓解 |
|---|---|---|
| 控制器改 view 后共享数据丢失 | 中 | 统一用 View composer / Blade 全局，先列数据清单再改 |
| fileinfo 缺失导致头像上传失败 | 中 | ADR-6 校验策略调整；或在宝塔尝试装预编译扩展 |
| Blade 重写工作量超预期 | 中 | 按页面优先级排：公开页 → 认证 → 个人 → 后台 → Setup |
| 阶段 1 修复引入行为偏差 | 低 | 每项 P0 单独 commit；`migrate:fresh` 验证 |
| 设计稿未定稿阻塞阶段 2.4 | 中 | 可先按现有 Tesla 风格占位，设计稿到位后替换 |

**回滚**：每阶段独立 PR/commit；`git revert` 回退到上一稳定态。阶段 2 与阶段 1 解耦，阶段 2 期间随时可回到"Inertia 修复版"。

## 11. 决策记录（ADR）

| # | 决策 | 结论 |
|---|---|---|
| ADR-1 | 重构方式 | 渐进式重构：保留 Laravel 后端，重写前端，非全量重写 |
| ADR-2 | **技术路线** | **方案B：去 Inertia → Laravel + Blade + Alpine + 静态 Tailwind**（2026-08-13 用户确认） |
| ADR-3 | 前端构建 | **工作站构建静态 CSS/JS 入库**，服务器零构建、零 CDN 依赖 |
| ADR-4 | 交互层 | Alpine.js（单文件，离线引用），覆盖批量选择/弹窗确认 |
| ADR-5 | 权限模型 | 保留 Middleware + Policy 双重校验（既有设计） |
| ADR-6 | **fileinfo 缺失** | ✅ **已实施**（commit `6509f0a`）：头像上传去掉依赖 finfo/GD 的 `mimes`/`image` 规则，改扩展名白名单 + 可选 GD `getimagesize`（`function_exists` 守卫，缺 GD 优雅跳过）。服务器内存不足无法编译 fileinfo，故不走"装扩展"路线 |
| ADR-7 | Laravel 版本 | 统一到 Laravel 11（`app.php` 去 `setup` 参数，`setup.php` 并入 `web.php`） |
| ADR-8 | 数据库 | 维持 MariaDB 5.7 兼容（string 替代 enum） |
